## 1. Basic Introduction

### What is this file?
`rag/confidence.py` is the **Multi-Signal Confidence Estimation Engine**. It calculates an explainable, composite confidence score ($\in [0.0, 1.0]$) for every answer generated by the system by synthesizing six independent retrieval, entity, and verification signals.

### Why is this file needed?
Most RAG systems either provide no confidence score or output a misleading single number (such as raw LLM softmax probabilities, which are notoriously uncalibrated and overconfident). 

In legal question answering, confidence must be **transparent, multi-faceted, and auditable**:
- Did the search engine find strong neural semantic matches?
- Was there sufficient supporting evidence (or just a single isolated chunk)?
- Did the retrieved documents actually match the statutory entities mentioned by the user?
- Did BM25 keyword search and dense vector search agree with each other?
- Did the citations pass structural validation without ungrounded hallucinations?
- Did the retrieved passages cover the key words in the user's question?

`rag/confidence.py` calculates each of these 6 signals independently, applies calibrated weights, and exposes the full breakdown to the Streamlit UI.

## 3. The 6 Transparent Confidence Signals

$$\text{Confidence} = \sum_{i=1}^{6} w_i \cdot S_i$$

```
┌────────────────────────────────────────────────────────────────────────┐
│                   6-SIGNAL CONFIDENCE ARCHITECTURE                     │
├──────────────────────────┬───────────┬─────────────────────────────────┤
│ Signal Name              │ Weight    │ Measurement Technique           │
├──────────────────────────┼───────────┼─────────────────────────────────┤
│ 1. Retrieval Strength    │   0.25    │ Sigmoid of Cross-Encoder Logit  │
│ 2. Evidence Count        │   0.15    │ min(1.0, Chunk Count / 3.0)     │
│ 3. Entity Alignment      │   0.20    │ Proportion of query entities hit│
│ 4. Method Agreement      │   0.15    │ Jaccard Overlap (BM25 ∩ Dense)  │
│ 5. Citation Integrity    │   0.15    │ Structural Validation Score     │
│ 6. Evidence Coverage     │   0.10    │ Ratio of query terms in evidence│
└──────────────────────────┴───────────┴─────────────────────────────────┘
```

### Detailed Breakdown of Each Signal:

#### Signal 1: Retrieval Strength ($w_1 = 0.25$)
If cross-encoder reranking was used, the top passage's score is an unconstrained logit $s \in (-\infty, +\infty)$. This is mapped to $[0.0, 1.0]$ via the standard logistic sigmoid:
$$\sigma(s) = \frac{1}{1 + e^{-s}}$$
- Logit $= +3.0 \to \sigma(s) \approx 0.95$ (Strong relevance)
- Logit $= 0.0 \to \sigma(s) = 0.50$ (Neutral)
- Logit $= -3.0 \to \sigma(s) \approx 0.05$ (Weak relevance)

#### Signal 2: Evidence Count ($w_2 = 0.15$)
A legal argument supported by multiple independent clauses or judicial holdings is far more reliable than one resting on a single isolated passage:
$$S_2 = \min\left(1.0, \frac{\text{count}}{3.0}\right)$$
- 1 passage $\to 0.33$
- 2 passages $\to 0.67$
- 3 or more passages $\to 1.00$

#### Signal 3: Entity Alignment ($w_3 = 0.20$)
If the user's query extracted entities (e.g. `Article 21`, `Puttaswamy`), does the retrieved parent evidence actually contain them?
- If query specified entities: $S_3 = 0.20 + 0.80 \times \left(\frac{\text{matched entities}}{\text{total query entities}}\right)$.
- If query had no named entities: defaults to a neutral baseline of $0.70$.

#### Signal 4: Method Agreement ($w_4 = 0.15$)
Measures consensus between lexical keyword matching (BM25) and dense semantic vector search (BGE-M3) using the Jaccard similarity coefficient across their top 5 candidates:
$$J = \frac{|\text{Top 5}_{\text{BM25}} \cap \text{Top 5}_{\text{Dense}}|}{|\text{Top 5}_{\text{BM25}} \cup \text{Top 5}_{\text{Dense}}|}$$
$$S_4 = 0.50 + 0.50 \times J$$

#### Signal 5: Citation Integrity ($w_5 = 0.15$)
Directly inherits `validation_score` from `CitationValidator`. Penalizes unretrieved citations, missing metadata, and NLI contradictions.

#### Signal 6: Evidence Coverage ($w_6 = 0.10$)
Calculates the fraction of meaningful query terms ($\ge 3$ characters) present in the retrieved passages:
$$S_6 = \frac{\sum_{w \in Q} \mathbb{I}(w \in \text{Evidence})}{|Q|}$$

## 4. Confidence Categorization

Once the weighted composite score is computed, it is categorized into one of four qualitative operational bands:

| Score Range | Confidence Level | Pipeline Action |
| :--- | :--- | :--- |
| **0.70 – 1.00** | **HIGH** | Full answer displayed; green confidence badge in UI. |
| **0.50 – 0.69** | **MEDIUM** | Answer displayed with caution notice; amber confidence badge. |
| **0.30 – 0.49** | **LOW** | Answer displayed with prominent limitation disclaimer; yellow badge. |
| **< 0.30** | **VERY_LOW** | **ABSTAIN**: Answer withheld by `AbstentionManager`; safe refusal notice displayed. |

## 6. Viva Presentation & Defense Q&A

### Q1: Why not just use the LLM's own self-reported confidence score?
> **Student Answer**:
> *"Research has proven that Large Language Models exhibit severe overconfidence bias—when hallucinating completely false facts, LLMs frequently claim 95% to 99% confidence! Relying on self-reported verbal confidence is dangerous in high-stakes legal domains. Our `ConfidenceEstimator` computes confidence objectively outside the LLM, synthesizing empirical search strength, cross-method consensus, statutory entity alignment, and deterministic citation validation."*

### Q2: What happens when the composite confidence score drops below 0.30?
> **Student Answer**:
> *"A score below 0.30 falls into the `VERY_LOW` band. In Stage 17, our `AbstentionManager` evaluates this score against the safety threshold `CONFIDENCE_ABSTENTION_THRESHOLD = 0.30`. If the score is below 0.30, the system refuses to show the generated answer. Instead, it displays a transparent refusal message explaining that available legal evidence was insufficient to guarantee a reliable answer."*
