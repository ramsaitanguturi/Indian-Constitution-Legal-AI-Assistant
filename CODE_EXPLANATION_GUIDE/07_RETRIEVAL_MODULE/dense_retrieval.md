## 1. Basic Introduction

### What is this file?
[`retrieval/dense_retriever.py`](../../retrieval/dense_retriever.py) is the standalone dense semantic retriever. It queries the persistent ChromaDB collection using continuous vector representations generated by `BAAI/bge-m3` (1024-d) or `all-MiniLM-L6-v2` (384-d).

### Why does this file exist?
While BM25 relies on exact word matches, `DenseRetriever` understands **conceptual semantic equivalence**:
- It recognizes that *"right to clean air and water"* is semantically similar to *"protection of life under Article 21"*.
- It recognizes that *"search without warrant"* relates to *"arbitrary executive intrusion"*.

It provides an independent retrieval interface adhering strictly to the repository's standardized candidate schema.

## 4. Key Method: `retrieve(query, top_k=20, filter_doc_type=None)`

- **Lines in Source**: [Lines 83–191](../../retrieval/dense_retriever.py#L83-L191)
- **Input Parameters**:
  - `query` (str): Search question.
  - `top_k` (int): Number of candidates to return (default 20).
  - `filter_doc_type` (Optional[str]): Metadata filter (`"constitution"`, `"judgment"`, or `None`).

### Execution Algorithm:
1. **Input Validation**: Rejects empty strings, whitespace, or strings without alphanumeric tokens.
2. **Collection Check**: Verifies `self.collection.count() > 0`.
3. **ChromaDB Query**:
   ```python
   query_kwargs = {
       "query_texts": [query],
       "n_results": min(top_k, count),
       "include": ["documents", "metadatas", "distances"],
   }
   if filter_doc_type:
       query_kwargs["where"] = {"doc_type": filter_doc_type}
   ```
4. **Cosine Distance to Similarity Conversion** (Lines 144–147):
   - ChromaDB calculates cosine distance:
     $$\text{dist} = 1.0 - \cos(\vec{u}, \vec{v}) \in [0.0, 2.0]$$
   - `DenseRetriever` converts distance into an intuitive similarity score in $[0.0, 1.0]$:
     $$\text{Similarity} = \max\Big(0.0, \, \min\big(1.0, \, 1.0 - \text{dist}\big)\Big)$$
5. **Parent Metadata Hydration** (Lines 150–162):
   - Looks up `parent_id` in `self.parent_store` to resolve statutory titles, citations, and judgment benches.
6. **Standardized Candidate Schema** (Lines 164–180):
   - Packages each candidate into a dictionary containing: `document_id`, `chunk_id`, `score`, `rank`, `text`, `doc_type`, and `metadata`.

## 5. Actual Code Walkthrough

### Code Excerpt: Cosine Similarity Inversion & Schema
```python
# Lines 144-170 in retrieval/dense_retriever.py
# Cosine similarity conversion: score = 1 - distance, clamped to [0.0, 1.0]
# ChromaDB cosine distance is in [0, 2]
cosine_sim = max(0.0, min(1.0, 1.0 - float(dist)))
similarity_score = round(cosine_sim, 4)

# Hydrate parent data
parent_data = self.parent_store.get(parent_id, {})
merged_metadata = {
    "parent_id": parent_id,
    "article_number": meta.get("article_number", parent_data.get("article_number", "")),
    "case_name": meta.get("case_name", parent_data.get("case_name", "")),
    "title": meta.get("title", parent_data.get("title", "")),
    "citation": meta.get("citation", parent_data.get("citation", "")),
    "year": meta.get("year", parent_data.get("year", 0)),
    "raw_distance": float(dist),
    "parent_data": parent_data,
}

candidate = {
    "document_id": parent_id,
    "chunk_id": chunk_id,
    "score": similarity_score,
    "rank": rank,
    "text": doc_text or "",
    "doc_type": meta.get("doc_type", "legal_document"),
    "metadata": merged_metadata,
}
```
- **Explanation**: Transforms raw vector distances into intuitive $[0, 1]$ similarity metrics and enriches the candidate with parent statutory details.
- **Why is this needed?**: Allows Reciprocal Rank Fusion and downstream rerankers to receive clean, uniformly formatted candidate records.
